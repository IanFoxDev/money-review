# Eval run 2026-10-06, new and rebuilt cases on the SQL app

Claude Code 2.1.289, reviewer Sonnet, verifier Opus, every case three times, on
`eval/app`, with the rules and triage of master after 0.3.0 (suppression added, no
checklist changes).

What changed in the case set:

- Two IDEM cases were rebuilt. In the old versions the change removed one of two
  safety layers and the other still held, so the verifier was right to drop them.
  `idem-dedup-outside-transaction` now also adds bank transfer deposits, where the
  event dedup is the only guard (a new deposit row per delivery, so the ledger key is
  new too). `idem-payout-rerun` is replaced by `idem-cashback-rerun`: cashback paid
  from an expense account that may go negative, keyed by the run date instead of the
  period, so a re-run on another day pays again and no balance check stops it.
- New cases for rules that had none: `money-commission-rounding` (MONEY-3, half up in
  the ledger and truncation in the partner statement), `money-refund-sign` (MONEY-5,
  positive refunds summed with payments), `tx-nested-payout-email` (TX-5, an email
  sent after an inner commit that is only a savepoint).
- Three clean cases that pair with them: one rounding helper used everywhere, refunds
  turned negative before the sum, the email sent with `DB::afterCommit`.

Notes on the two lost points:

- Missed: in one run of `tx-nested-payout-email` the reviewer reported the right bug
  (TX-5, high, the right scenario) at line 1 of the file. The scorer counts it as a
  miss. `fix-lines.sh` only moves findings past the end of a file, so line 1 went
  through; a review comment there would point at `<?php`.
- False alarm: RACE-6 low in the same case, "the daily limit counts only the current
  batch". It holds only if the job runs more than once a day, which the case does not
  say. Left as a false alarm, the case was not changed after the run.
