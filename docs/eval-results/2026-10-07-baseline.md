# Eval run 2026-10-07, full baseline for 0.6.0

Every case of both apps, three times each, on `0144576` (master with `--commits`, the
review itself as in 0.5.2). This run replaces the baseline in
`eval/baseline/summary.json`.

Why a new baseline: the earlier runs kept the working copies of the cases inside the
repository, and Claude Code loads the CLAUDE.md files of every parent directory. On the
maintainer's machine that put an unrelated CLAUDE.md into the context of every review.
Since this run the working copies are built in a temporary directory (`eval/workdir.sh`),
so a review sees only the case. The numbers did not move: the old setup did not help
the reviews.

The report format changed after this run started (code excerpts, a table, "How to
fix"). That is done by scripts after the review and does not change the findings.

Compared with the 2026-10-06 baseline (`eval/compare.sh`): no regression. The one case
that differs is `tx-nested-payout-email`: the RACE-6 low "the daily limit counts only the
current batch" came 2 times in 3 instead of once. It holds only if the job runs more
than once a day, which the case does not say; it stays counted as a false alarm.

`clean-avatar-upload` and `mongo-clean-relay-batch` are skipped by triage, as before.
