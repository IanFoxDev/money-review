# Eval run 2026-10-08: new rules, MONEY-0, harder cases

What changed since [2026-10-07-baseline.md](2026-10-07-baseline.md), after the comparison
with a plain prompt ([2026-10-07-plain-prompt.md](2026-10-07-plain-prompt.md)) showed
that money-review missed real money bugs next to the planted ones:

- the reviewer may report a money bug that no rule covers, as `MONEY-0`, with the same
  bar (a concrete failure scenario); before, it could only report checklist rules;
- new rules MONEY-7 (amount from the wrong source), TX-9 (event contract for money
  consumers), IDEM-10 (provider declines and business errors with no path), and MONEY-5
  covers negative input amounts and reversals in the wrong direction;
- the verifier moves a real finding to the rule that fits instead of rejecting it;
- ten cases got the second bug that the comparison found and checked against the code
  (`note` in `case.json`), one new case (`money-chargeback-wrong-amount`), and two clean
  cases that had real bugs were fixed (`clean-chargeback-webhook`,
  `clean-commission-rounding`). 50 cases, 53 bugs.

the missing ledger entry). The report then has one finding instead of two; the eval
counts the second bug as missed.

## How the after run was put together

The full run is on `24ef4f9`. Two cases were run again and replace their first runs:

- `clean-chargeback-webhook`: the first run raised IDEM-10 "a chargeback over what is left
  of the payment is refused, so money the provider took is never booked". That was right
  by the new IDEM-10 rule and wrong in the case, which refused it. The case now books it
  and logs it for reconciliation. On the new version money-review, opus and sonnet said
  nothing, three runs each.
- `tx-refund-call-in-transaction`: one run hung for over an hour. The coordinator had
  started the reviewer as a background agent, and the headless run waited for it until
  Claude Code stopped it, with no report. The skill now says to run the agents in the
  foreground. The case was run again, three of three.

Two `acceptable` entries were added after reading the findings: MONEY-7 and MONEY-5 in
`idem-chargeback-webhook-no-dedup` (the chargeback amount is not checked against the
payment), IDEM-10 in `money-chargeback-wrong-amount` (the old code drops a chargeback for
a payment that is not `succeeded` after recording the event).

The plain prompt numbers are the 2026-10-07 runs for the unchanged cases and new runs
for the three changed ones.
